## Founder simplification and Codex N1–N4

**Founder direction (2026-10-20):** Obsidian is an optional **snapshot viewer**, not a canonical database, an always-current replica, a synchronized memory subsystem, a security boundary enforcing Forget across exported copies, or an editing surface. The user explicitly requests an export; Sovereign reads one authorized snapshot, renders Markdown with working `[[wikilinks]]`, verifies it, and delivers a ZIP or a newly created folder; the user regenerates it by hand when wanted. This supersedes revision 3's managed projection and its automatic Forget cleanup (old D8) and makes the persistent registry (old D14) unnecessary for V0.

| Finding | Disposition under the snapshot model | Where |
| --- | --- | --- |
| **N1** Multi-version ownership recovery (a registry managing several generations and file copies could fail to recover ownership) | **Not applicable.** V0 has no persistent registry, no multi-generation hash ledger and no ownership recovery: an export is written once into a fresh location and never revisited. The complex protocol was removed rather than repaired | Export spec §11.4–§11.5 |
| **N2** Crash atomicity and generation consistency | **Resolved by not claiming either.** No atomic multi-file publication, power-loss recovery, SQLite write lock across file writes or cross-process recovery is promised. Staging, failure reporting and verification remain: a failed export is reported as failed and removes its own temporary files on a best-effort basis, an interrupted one reports nothing and leaves no partial or unverified result under the destination name (at most a hidden, recognizably named leftover beside it), neither is ever reported as complete, nothing partial or unverified ever appears under the destination name, and the next export starts fresh | Export spec §11.1, §11.5; validation spec 27 |
| **N3** Excluded-ID leakage verification (a free-text scan for excluded canonical IDs fails on IDs that coincide with ordinary words) | **Retained and corrected.** Verification is typed and structural — the file set, filenames, frontmatter values, generated lines, inert-block contents and every link against the authorized edge set — and never scans free text for excluded IDs. Only exporter-generated links can form graph relationships; untrusted text stays inert. Canaries remain a test-time device | Export spec §11.3; validation spec 24a |
| **N4** Filename length | **Retained.** The final UTF-8 basename — title, handle after collision extension, and `.md` — is at most 140 bytes, with titles cut by bytes at a word or character boundary and never splitting a code point; relative paths at most 160 bytes | Export spec §5; validation spec 2 |

**What was intentionally removed** (as V0 obligations): the projection registry and its per-file ownership hashes; registration before writing; the vault write lock held from snapshot to final directory sync; verify-and-promote crash recovery; automatic, start-up, periodic and Forget-triggered reconciliation; vault-identity and tombstone-prefix tracking; per-projection pending, `needs_attention` and re-binding states; the Forget preview's per-projection file counts; in-place updates of an existing export folder. An in-place refresh may be proposed later as a separately evaluated, user-confirmed operation that protects user edits (D9).

**What did not change:** canonical Forget, evidence identity and supersession, MemoryClaim authority and the Context Compiler policy, including the truncation fingerprint, ADR-0004 decision 3, the budgets and disclosure eligibility. Sensitive items stay excluded from exports by default, and the Security Gate remains NOT PASSED.

**Still blocking production SB-2:** the pre-existing hidden-rowid replacement defect in the ADR-0003 storage triggers (SECURITY-GATE), confirmed by the independent Codex audit. It is a high-priority Tier 2 storage-integrity repair, outside PR #3.

## Final review rounds

After the dispositions above were first written, the documents went through four more independent rounds. Each finding was checked against the files, the code and PR #4's data before it was applied.

- **Cross-document review** (memory authority and Context Compiler, PR #4 reconciliation, repository consistency), applied in `0333904`, `a82cf3a` and `22710f4`. It named the ADR-0004 amendments later slices would need (entity-aware sensitivity, entity identity pinning, weighted-score staleness), stated the unmeasured gaps (unchanged-vault token stability, questions with no relevant item), recorded PR #4's decisions 1, 2 and 6 as open, and aligned D7, D9, titles, banners and labels.
- *(History: the export protocol this round changed is revision 2, superseded and preserved in `11b2f4b`.)* **Completeness critic** against the founder's brief, two critics with one adversarial verifier per finding, applied in `2bcb430` and `6971467`. Of 21 findings, 13 were confirmed or partially confirmed; the other 8 had already been fixed by the time they were verified; none was rejected on substance. It found one **blocker that an earlier F2 fix had introduced**: the vault identity fingerprinted the whole tombstone sets, so every Forget would have looked like a different vault and stopped reconciliation before any deletion. The registry then kept, per tombstone table, the count and a keyed fingerprint of the insertion-ordered prefix (revision 2 §11.1, §11.3 and §11.5 at `11b2f4b`); a probe on a scratch vault had confirmed that the prefix survives further Forgets, that duplicate tombstone inserts are ignored, and that a vault rebuilt by trusted restore is flagged when its export order differs from the original insertion order (otherwise its tombstone tables are identical — a residual of revision 2 §11.5 at `11b2f4b`).
- *(History: revision 2, superseded.)* **Final attack on the redesigned rule** (an F2 race-hunter against `store.py` and a regression hunter over `22710f4..ddaff0e`, each finding verified), applied in the following commit. It found that an anomaly would have cleared itself after one run (step 8 was changed to keep the stored state until a confirmed re-binding), that a Forget still pending when the vault file is reverted could be re-authorized (`delete_pending` entries were made never re-authorized), a generation mismatch after a crash between publication and registry commit, and invariant wording that ignored the stored tombstone state. It also found a **pre-existing storage defect on `main`**, reproduced here: a raw-SQL `INSERT OR REPLACE` that names an existing rowid bypasses the ADR-0003 triggers, replacing a tombstone or deleting a record without one. PR #3 changes no code; the defect is recorded in SECURITY-GATE, the export spec (now §11.2), ROADMAP §G and validation item 35 as a prerequisite Tier 2 storage fix with independent review.
- **Snapshot-export review** (after the founder simplification: a contract attacker, an obsolete-reference sweep and a PR #4/invariants check, each finding verified), applied in the commit after `ff66b32`: ADR-0005 invariant 5 narrowed to the stores Sovereign manages; no export deletes other runs' leftovers (it lists them); no copy fallback, and the no-replace primitives are named; vault-open locking and the exact snapshot point stated; ZIP archives written beside their destination without a staging tree; Git working trees always refused and sync detection stated as best effort; structural verification covers every generated value; `export_id` derived from the export key; titles keep modifier letters and combining marks; stale registry wording removed from this record.
