## Founder simplification and Codex N1–N4

**Founder direction (2026-10-20):** Obsidian is an optional **snapshot viewer**, not a canonical database, an always-current replica, a synchronized memory subsystem, a security boundary enforcing Forget across exported copies, or an editing surface. The user explicitly requests an export; Sovereign reads one authorized snapshot, renders Markdown with working `[[wikilinks]]`, verifies it, and delivers a ZIP or a newly created folder; the user regenerates it by hand when wanted. This supersedes the managed projection of ADR-0005 revision 3 (export spec revision 2) and its automatic Forget cleanup (old D8) and makes the persistent registry (old D14) unnecessary for V0.

| Finding | Disposition under the snapshot model | Where |
| --- | --- | --- |
| **N1** Multi-version ownership recovery (a registry managing several generations and file copies could fail to recover ownership) | **Not applicable.** V0 has no persistent registry, no multi-generation hash ledger and no ownership recovery: an export is written once into a fresh location and never revisited. The complex protocol was removed rather than repaired | Export spec §11.4–§11.5 |
| **N2** Crash atomicity and generation consistency | **Resolved by not claiming either.** No atomic multi-file publication, power-loss recovery, SQLite write lock across file writes or cross-process recovery is promised. Staging, failure reporting and verification remain: a failed export is reported as failed and removes its own temporary files on a best-effort basis, an interrupted process reports nothing and leaves no partial or unverified result under the destination name (at most a hidden, recognizably named leftover beside it), neither is ever reported as complete, and the next export starts fresh. After an OS crash, power loss or storage failure **no guarantee** is made: flushing is best effort, not durability, and any export produced around such an event is treated as potentially invalid and regenerated | Export spec §11.1 (*Outcomes by kind of event*), §11.5; validation spec 27–27a |
| **N3** Excluded-ID leakage verification (a free-text scan for excluded canonical IDs fails on IDs that coincide with ordinary words) | **Retained and corrected.** Verification is typed and structural — the file set, filenames, frontmatter values, generated lines, inert-block contents and every link against the authorized edge set — and never scans free text for excluded IDs. Only exporter-generated links can form graph relationships; untrusted text stays inert. Canaries remain a test-time device | Export spec §11.3; validation spec 24a |
| **N4** Filename length | **Retained.** The final UTF-8 basename — title, handle after collision extension, and `.md` — is at most 140 bytes, with titles truncated by Unicode extended grapheme clusters (UAX #29, pinned Unicode version) to whole clusters that fit both a 60-cluster cap and the byte budget, never splitting a code point or cluster, falling back to the fixed ASCII `Untitled <kind>` if no cluster fits; relative paths at most 160 bytes | Export spec §5; validation spec 2 |

**What was intentionally removed** (as V0 obligations): the projection registry and its per-file ownership hashes; registration before writing; the vault write lock held from snapshot to final directory sync; verify-and-promote crash recovery; automatic, start-up, periodic and Forget-triggered reconciliation; vault-identity and tombstone-prefix tracking; per-projection pending, `needs_attention` and re-binding states; the Forget preview's per-projection file counts; in-place updates of an existing export folder. An in-place refresh may be proposed later as a separately evaluated, user-confirmed operation that protects user edits (D9).

**What did not change:** canonical Forget, evidence identity and supersession, MemoryClaim authority and the Context Compiler policy, including the truncation fingerprint, ADR-0004 decision 3, the budgets and disclosure eligibility. Sensitive items stay excluded from exports by default, and the Security Gate remains NOT PASSED.

**Still blocking production SB-2:** the pre-existing hidden-rowid replacement defect in the ADR-0003 storage triggers (SECURITY-GATE), confirmed by the independent Codex audit. It is a high-priority Tier 2 storage-integrity repair, outside PR #3.

### Final N2 and N4 corrections (after the last Codex audit: CONDITIONAL PASS, N1 and N3 closed)

- **N2 — power-loss guarantees.** The spec no longer claims that flushing (`fsync`, `F_FULLFSYNC`, `FlushFileBuffers`), rename ordering or read-back makes an export durable. Export spec §11.1 now separates three outcomes: normal completion; process interruption or termination (nothing reported, nothing partial or unverified under the destination name); and OS crash, power loss or filesystem/hardware failure, where **no guarantee** is made and any affected export must be treated as potentially invalid and regenerated. Flushing and no-replace publication remain as best-effort measures. Validation item 27 is split into required process-failure tests and platform-specific, recorded power-loss tests (27a). The ADR, this record and the PR description were aligned.
- **N4 — grapheme segmentation.** The "character plus combining marks" approximation is replaced by Unicode extended grapheme clusters (UAX #29) at a pinned Unicode version, applied to the sanitized NFC title, with the 140-byte basename limit, collision-extended handles in the budget, a deterministic ASCII fallback and no mandated library. Validation item 2 adds Hangul conjoining Jamo (including the U+1100 counterexample), Indic conjuncts, combining-mark sequences, multibyte text, and handle extension with tight budgets.

### Audit closure (2026-10-21)

Codex's final verification of the head `591c011027cddcd9383941bbde60075ec54c3935` closed **N2** and **N4** — **PASS at the specification level**, with the two conditions of its previous verdict satisfied:

- **N2 closed:** the contract distinguishes process interruption from OS or storage failure; no power-loss or crash durability is promised and flushing or read-back does not establish it; an interrupted exporter, while the OS keeps running, reports no success and publishes no partial or unverified result; termination after publication may leave a complete, verified but unreported export; after an OS crash, power loss or storage failure affected exports are treated as potentially invalid and regenerated (export spec §11, §11.4–§11.5; ADR-0005 §9; validation 27–27a).
- **N4 closed:** UAX #29 extended grapheme clusters with one pinned Unicode version for normalization, categories and segmentation, recorded in the export report; a complete basename of at most 140 bytes including the collision-extended handle and `.md`; whole-cluster truncation without splitting code points or altering handles; `Untitled <kind>` when the result is empty or the first cluster cannot fit; validation against `GraphemeBreakTest` including U+1100 U+1100 U+1161, oversized Jamo clusters, क्ष / त्र and tight budgets (export spec §5; validation 2).

With N1 (not applicable) and N3 (closed) before them, every Codex finding on PR #3 — F1–F6 and N1–N4 — is closed at the documentation level. This was specification verification only: the native Obsidian tests, the platform-specific power-loss tests (27a), the grapheme acceptance tests and every SB-2 implementation gate remain open, and the SQLite hidden-rowid repair remains a separate high-priority Tier 2 prerequisite. On 2026-10-21 the founder approved ADR-0005's architectural direction (D1–D14) and R1–R7 as planning positions and deferred D15 ([ADR-0005 §15.1](../adr/0005-governed-second-brain-architecture.md#151-founder-decision-record-2026-10-21)).
